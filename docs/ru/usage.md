## Как запускается skill

Большинство агентов запускают skill автоматически, если запрос касается
понятного технического текста на любом языке, документации или
ASD-STE100. Skill можно вызвать и явно:

- в Claude Code после установки плагина:
  `/controlled-language:controlled-language <запрос>`;
- в Claude Code после установки папкой: `/controlled-language <запрос>`;
- в других агентах: напишите в запросе «Use the controlled-language skill».

## Режимы

### Написание (write)

Укажите тему и факты. Skill напишет новый документ.

```
Write the installation guide for our CLI in controlled English.
Facts: Node.js 20 or later. Install with `npm i -g acme-cli`.
Run `acme login` once. The config is in ~/.acme/config.json.
```

### Переписывание (rewrite)

Дайте текст или файл. Skill приведёт текст к уровню и сохранит факты.

```
Rewrite docs/upgrade.md at Level 2. Edit the file in place.
```

После текста skill выводит короткий блок «Notes»:

- уровень и его источник;
- кандидаты в глоссарий (найденные термины);
- слова для проверки (только уровень 3);
- вопросы (например, о значении, которого нет в исходном тексте).

### Проверка (review)

Дайте текст или файл. Skill выдаст отчёт. В каждой строке отчёта: номер
строки, номер правила, проблема и исправление.

```
Review README.md at Level 3. Do not change the file.
```

В отчёте три типа замечаний:

| Тип | Значение |
| --- | --- |
| Violation (нарушение) | Текст нарушает обязательное правило уровня. |
| Warning (предупреждение) | Текст, возможно, нарушает правило. Решает человек. |
| Suggestion (рекомендация) | Текст нарушает рекомендуемое правило уровня. |

### Ответы (respond)

Попросите агента отвечать на контролируемом английском. Режим действует,
пока вы его не отключите.

```
From now on, answer in controlled English, Level 2.
Explain how database indexes work.
```

## Выбор уровня

Укажите уровень в запросе:

| Вы пишете | Уровень |
| --- | --- |
| «Level 1», «light», «relaxed», «50%», «мягко» | 1 |
| «Level 2», «standard», «80% of the way to ASD-STE100» | 2 |
| «Level 3», «strict», «full STE», «100%», «строго» | 3 |

Если в запросе нет уровня, skill берёт его из front matter документа, затем
из конфигурационного файла проекта. По умолчанию — уровень 2. Подробнее —
в [levels.md](levels.md) и [configuration.md](configuration.md).

## Термины проекта

В вашем проекте есть свои слова: названия компонентов, экранов, типов
данных и действий. Skill их не упрощает. Каждый термин он пишет каждый раз
одинаково.

Для лучшего результата впишите термины в глоссарий файла
`.controlled-language.yml`:

```yaml
glossary:
  technical_nouns: [API key, webhook, dashboard]
  technical_verbs: [deploy, sign]
  preferred_terms:
    - use: sign in
      not: [log in, login]
```

Если глоссария нет, skill находит термины в контексте. В режимах
переписывания и проверки он выводит их как «Glossary candidates».
Скопируйте правильные термины в глоссарий.

## Что skill не меняет

Skill применяет правила только к тексту. Он не меняет:

- блоки кода, встроенный код и команды;
- имена файлов, пути, URL и адреса электронной почты;
- имена API, функций, переменных и полей;
- надписи интерфейса (с точным написанием заглавных букв);
- названия продуктов и строки из `keep_verbatim` в конфигурационном файле;
- цитаты, юридические тексты и текст между маркерами `off`.

## Тексты на других языках

Skill работает с текстом на любом языке. Английский — родной язык подхода.
К текстам на других языках skill применяет:

- 32 универсальных правила. Например: короткие предложения, условие перед
  действием, активный залог, один термин для одного понятия;
- правила языкового файла, если он есть для языка.

Языковые файлы есть для русского, немецкого, французского и испанского.
Для русского языка skill также:

- пишет инструкции в повелительном наклонении («Откройте», «Нажмите»);
- заменяет отглагольные существительные глаголами: «произведите настройку»
  → «настройте»;
- убирает канцелярит: «является», «осуществляется», «данный», «в целях»;
- сокращает цепочки существительных в родительном падеже;
- разбивает деепричастные обороты на отдельные шаги.

Подробнее — в
[languages.md](../../controlled-language/references/languages.md)
(на английском).

Все три уровня работают во всех языках. Уровень 3 в других языках делает
все правила обязательными, но не контролирует словарь: одобренный словарь
ASD-STE100 есть только для английского.

Skill сам определяет язык текста. Чтобы указать язык явно, напишите его
в запросе, добавьте `lang: ru` во front matter или задайте `language`
в конфигурационном файле. Чтобы skill не менял тексты на других языках,
задайте `non_english: off`.

## Скрипт проверки

Скрипт находит измеримые проблемы в тексте. Нужен Python 3.8 или новее,
других пакетов не нужно.

```bash
python3 controlled-language/scripts/check.py [параметры] ПУТЬ [ПУТЬ ...]
```

`ПУТЬ` — файл, папка или `-` (стандартный ввод). В папке скрипт читает
файлы `.md`, `.mdx`, `.markdown` и `.txt`.

| Параметр | Описание |
| --- | --- |
| `--level {1,2,3}` | Уровень для всех файлов. Без него скрипт берёт уровень из front matter, конфигурационного файла или использует уровень 2. |
| `--config ПУТЬ` | Конфигурационный файл. Без него скрипт ищет `.controlled-language.yml` в текущей папке и выше. |
| `--format {text,json}` | Формат вывода. По умолчанию — `text`. |
| `--fail-on {never,violation,warning}` | Завершиться с кодом 1, если найдено нарушение (или нарушение либо предупреждение). По умолчанию — `never`. |
| `--no-suggestions` | Не показывать рекомендации. |
| `--lang КОД` | Язык текста: `auto` (по умолчанию), `en` или код языка, например `ru`, `de`, `pt-BR`. `auto` определяет язык каждого файла. |
| `--word-list ПУТЬ` | Другой список английских слов. |
| `--languages-dir ПУТЬ` | Папка с языковыми файлами. |

Пример вывода:

```
docs/install.md:12: violation S2 Sentence has 27 words (max 20 in an instruction at Level 2) — "Open the terminal, go to the project folder and…"
docs/install.md:15: warning V1 Passive voice: "is read" — "The file is read at startup."
docs/install.md: Level 2 (config), en, 41 sentences (18 procedural, 23 descriptive): 3 violations, 2 warnings, 4 suggestions, 7.3 violations per 100 sentences
```

**Что скрипт находит во всех языках:**

- длинные предложения (S2) и длинные абзацы (D2);
- точки с запятой (S5);
- слова из таблицы замен языкового файла (например, RU2 и RU3 в русском);
- `avoid_words` и `preferred_terms` вашего проекта;
- предупреждения в примечаниях (SF2) — по словам-сигналам языкового файла.

В китайском, японском и тайском скрипт не считает длину предложений:
в этих языках нет пробелов между словами.

**Что скрипт дополнительно находит в английском тексте:**

- пассивный залог (V1);
- перфектные и длительные времена (V2);
- фразовые глаголы (V3);
- формы на «-ing» (W6);
- слова из [английского списка замен](../../controlled-language/references/word-choices.md);
- нерасшифрованные сокращения (W9);
- британское или американское написание (W8);
- инструкции в примечаниях (P5);
- предупреждения, которые начинаются не с команды (SF1);
- двойное отрицание (S6).

**Чего скрипт не находит:** смысловых проблем. Например:

- слово во втором значении;
- расплывчатое утверждение без «расплывчатых» слов;
- длинную цепочку существительных;
- шаг не на своём месте.

Для таких проблем используйте режим проверки (review) самого skill.

## Использование в CI

Добавьте скрипт в CI. Этот job GitHub Actions проверяет документацию
на уровне 2 и останавливает сборку при нарушении:

```yaml
name: Docs style
on: [pull_request]
jobs:
  controlled-language:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/checkout@v4
        with:
          repository: amaklakov-droid/controlled-language-skill
          path: .controlled-language-skill
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: >
          python .controlled-language-skill/controlled-language/scripts/check.py
          --fail-on violation README.md docs/
```

Для старой документации начните с `--fail-on never`. Исправьте нарушения,
затем замените параметр на `--fail-on violation`.

## Ограничения

- Skill и скрипт помогают автору. Они не заменяют обученного редактора.
- Уровень 3 опирается на знания модели об одобренном словаре ASD-STE100.
  Словаря в проекте нет. Skill перечисляет слова, в которых не уверен.
- Тексты, созданные с помощью skill, не сертифицированы на соответствие
  ASD-STE100. Для формальной проверки сверяйте текст
  с [официальным стандартом](https://www.asd-ste100.org/).
