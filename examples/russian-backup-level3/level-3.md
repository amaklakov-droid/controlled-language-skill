# Резервное копирование и восстановление базы данных

Этот раздел объясняет администратору, как создать резервную копию базы данных сервиса. Раздел также объясняет, как восстановить базу данных из резервной копии после сбоя.

## Создание резервной копии

Скрипт `backup.sh` создаёт резервную копию базы данных.

> **ОСТОРОЖНО:** Запускайте скрипт `backup.sh`, когда нагрузка на сервис минимальна. Пока скрипт работает, он может уменьшить производительность сервиса.

Чтобы создать резервную копию, выполните эти шаги:

1. Подключитесь к серверу по SSH.
2. Перейдите в каталог `/opt/app`.
3. Запустите скрипт `backup.sh`.

Скрипт сохраняет резервную копию в каталог `/var/backups/app`. Скрипт создаёт имя файла резервной копии автоматически на основе текущей даты.

## Восстановление из резервной копии

Скрипт `restore.sh` восстанавливает базу данных из резервной копии.

> **ВНИМАНИЕ:** Убедитесь, что вы выбрали правильный файл резервной копии, перед тем как запустить скрипт `restore.sh`. Этот скрипт безвозвратно удаляет все текущие данные в базе данных.

Запустите скрипт `restore.sh` с именем файла резервной копии в качестве параметра. Пример:

```bash
sudo ./restore.sh app-2026-10-01.dump
```

Скрипт заменяет все текущие данные в базе данных на данные из резервной копии.
